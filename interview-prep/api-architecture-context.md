## 2. Как со мной заниматься

Формат, который сложился и работает:

1. **Объяснение темы** — не пересказ урока, а разбор с акцентом на то, что спрашивают на собеседовании. Ключевые формулировки выделять, называть типичные ловушки.
2. **Тест из 5 вопросов** после темы.
3. **Разбор с баллами** по каждому вопросу и итоговым процентом.
4. **Обновление справочника** — сквозного конспекта по курсу.

Что помогает лично мне:

- **Маленькие конкретные примеры с таблицами.** Абстрактные объяснения не заходят, разбор «на пяти строках данных» заходит.
- **Пошаговый прогон механики** — «шаг 1 база делает то, шаг 2 это».
- Показывать, **что сломается**, если убрать часть конструкции.
- Связка с **финтех-доменом**: платежи, счета, проводки. На таких примерах запоминается лучше.

Что не помогает:

- Длинные теоретические простыни без примера.
- Давать сразу готовый ответ, когда я застрял на механике — лучше подсказку и дать доделать самому.

**Говори прямо, если я переоцениваю свой уровень.** Мне нужна честная оценка готовности к собеседованию, а не поддержка.

## 3. Мои повторяющиеся ошибки — следи за ними

Зафиксированы за несколько занятий, повторяются стабильно:

1. **Теряю уточняющие слова в определениях.** Отвечаю directionally верно, но неточно. Пример: «нужно подключение к сети» вместо «чаще всего требуется подключение».
2. **Отвечаю про не тот элемент.** Когда вопрос про конкретную вещь, применяю верное рассуждение к соседней. Пример: спросили про доли браузеров у аудитории — ответил про разделение фронтенда и бэкенда.
3. **Достраиваю правдоподобные детали**, которых в материале не было, вместо того чтобы признать неуверенность.
4. **Сужаю условие задачи.** Беру частный случай вместо запрошенного общего.
5. **Не отвечаю на все части составного вопроса.** Теряю баллы не от незнания, а от неполноты.
6. **Переношу шаблон решения на задачу, где он не применим.**

Если видишь эти паттерны — называй их прямо по номеру, это работает.

## 6. Как извлекать материал из Drive

Файлы — SingleFile HTML-снапшоты по 1–5 МБ, в основном base64-ассеты. Читать `read_file_content` их нельзя (не тот MIME), а грузить целиком в контекст нельзя по объёму.

**Рабочая схема:**

1. `download_file_content` по File ID.
2. Ответ двойно закодирован: `json.load` → `data[0]['text']` → `json.loads` → `inner['fileContent']`.
3. Содержимое — base64, декодировать.
4. Распарсить BeautifulSoup, взять видимый текст.
5. Отфильтровать строки длиннее 300 символов — это base64-мусор.
6. Убрать шапку Практикума, виджет поддержки, меню профиля, кнопку «К следующему уроку».

**Важно:** делать это в субагенте, иначе 5 МБ прилетят в основной контекст. Субагент должен вернуть чистый markdown с полным текстом урока — заголовки, определения, списки, примеры, вопросы для самопроверки с правильными ответами.

## 7. Чего в курсе нет, а на собеседовании спросят

Курс 2023 года, эти темы либо отсутствуют, либо даны поверхностно. Их нужно добирать отдельно:

**API:**
- Идемпотентность и ключ идемпотентности (`Idempotency-Key`) — вопрос номер один в платёжных командах
- OAuth 2.0, grant types, OpenID Connect, JWT (структура, почему payload не шифруется, отзыв токенов)
- Вебхуки: ретраи, подпись HMAC, порядок доставки, DLQ
- Пагинация offset vs cursor
- Версионирование API, breaking changes
- Rate limiting, 429, Retry-After
- gRPC и GraphQL в сравнении с REST
- Contract-first / design-first подход, OpenAPI

**Архитектура и асинхрон:**
- Kafka vs RabbitMQ, партиции, consumer groups, порядок сообщений
- Гарантии доставки: at-most-once, at-least-once, exactly-once
- Идемпотентный потребитель, дедупликация
- Saga: оркестрация vs хореография, компенсирующие транзакции
- Двухфазный коммит и почему его избегают
- Outbox pattern
- CAP-теорема, eventual consistency
- API Gateway
- Кэширование и инвалидация

**Финтех-домен:**
- Эквайринг: участники и поток денег
- Авторизация vs списание (hold/capture), 3-D Secure и liability shift
- СБП и отличия от карточных платежей
- ISO 8583 / ISO 20022, MCC
- Двойная запись, леджер, проводки, сторно
- Сверка (реконсиляция)
- 152-ФЗ, 115-ФЗ, 161-ФЗ, PCI DSS, маскирование PAN

## 9. С чего начать в новом чате

Предлагаемый порядок, но подстраивайся:

1. **Сначала сеть и HTTP** — модуль «Программные интерфейсы», уроки 02–06. Без понимания HTTP разговор про REST будет пустым. Особенно: методы, идемпотентность методов, коды ответов, где что передаётся (path, query, header, body).
2. **JSON и XML** — уроки 07–08, быстро.
3. **REST и SOAP** — уроки 13–14, плюс внешние темы: OpenAPI, версионирование, пагинация, аутентификация.
4. **Стили взаимодействия и обмен сообщениями** — уроки 11–12, плюс внешние: Kafka, гарантии доставки, идемпотентный потребитель.
5. **Архитектура** — модуль 1 целиком, уроки 02–13. Клиент-сервер, звенья, слои, SOA, микросервисы, масштабный куб, диаграммы компонентов и развёртывания.
6. **Проектирование API** — часть 7, модуль 01, все 7 уроков. Там сквозной проект, его стоит сделать целиком — это портфолио.
7. **Тестирование** — часть 7, модуль 02, уроки 06–08.
8. **Финтех-домен** — отдельным блоком, из внешних материалов.

По каждой теме: разбор → 5 вопросов → баллы → блок в справочник.

Практику давать на моей финтех-базе и на кейсах вида «спроектируйте эндпоинт создания платежа» — с идемпотентностью, кодами ответов, структурой ошибки, sequence-диаграммой.
